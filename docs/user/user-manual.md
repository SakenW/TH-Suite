# TH-Suite v2.0 用户操作手册

## 欢迎使用 TH-Suite

TH-Suite v2.0 是专为 Minecraft 模组和资源包本地化设计的专业工具。本手册将引导您完成从安装到熟练使用的全过程。

## 快速开始

### 系统要求

- **操作系统**: Windows 10+, macOS 10.15+, 或 Linux
- **内存**: 最少 4GB RAM，推荐 8GB+
- **存储**: 至少 2GB 可用空间
- **网络**: 稳定的互联网连接（用于 Trans-Hub 同步）

### 安装 TH-Suite

#### 下载和安装
1. 访问 [TH-Suite 官网](https://th-suite.trans-hub.net) 下载最新版本
2. 运行安装程序，按照向导完成安装
3. 首次启动时，工具会自动检查和配置必要组件

#### 初始配置
1. **Trans-Hub 账户连接**
   - 在设置页面中输入您的 Trans-Hub API 密钥
   - 测试连接确保同步功能正常
   
2. **工作目录设置**
   - 选择您的 Minecraft 项目存放目录
   - 建议使用专门的文件夹管理所有项目

### 核心概念

#### 项目（Project）
- **MOD 项目**: 包含一个或多个 Minecraft 模组的翻译项目
- **资源包项目**: 针对 Minecraft 资源包的本地化项目
- 每个项目包含源语言和目标语言配置

#### 扫描（Scan）
- **完整扫描**: 扫描项目中所有文件，提取可翻译内容
- **增量扫描**: 只处理自上次扫描后发生变化的文件
- **快速扫描**: 仅扫描已知的语言文件位置

#### 同步（Sync）
- **推送**: 将本地翻译上传到 Trans-Hub 平台
- **拉取**: 从 Trans-Hub 下载最新翻译
- **双向同步**: 同时进行推送和拉取，智能处理冲突

## 详细操作指南

### 1. 创建新项目

#### 步骤说明
1. **打开项目管理页面**
   - 点击侧边导航中的"项目管理"
   - 或在欢迎页点击"创建新项目"

2. **填写项目信息**
   ```
   项目名称: 我的模组翻译项目
   项目描述: Minecraft 模组本地化
   项目类型: MOD 项目 / 资源包项目
   项目路径: /path/to/your/minecraft/project
   ```

3. **配置语言设置**
   ```
   源语言: 英语 (en_us)
   目标语言: 简体中文 (zh_cn), 日语 (ja_jp)
   ```

4. **高级设置**（可选）
   ```
   MOD 加载器: Forge / Fabric / Quilt / NeoForge
   包含子目录: 是/否
   自动检测语言文件: 是/否
   ```

#### 项目类型说明

**MOD 项目特点**:
- 支持 JAR 文件扫描和处理
- 自动识别 MOD 加载器类型
- 智能提取 `assets/*/lang/` 目录下的语言文件
- 支持 `.json` 和 `.properties` 格式

**资源包项目特点**:
- 专注于资源包的语言文件
- 支持 `pack.mcmeta` 元数据
- 适用于纹理包、音效包等资源包本地化

### 2. 项目扫描

#### 启动扫描
1. **选择扫描类型**
   - **完整扫描**: 首次扫描或大更新后使用
   - **增量扫描**: 日常更新时使用，速度更快
   - **快速扫描**: 仅检查已知语言文件

2. **配置扫描选项**
   ```
   □ 包含 MOD 文件 (.jar)
   □ 包含资源包
   □ 递归扫描子目录
   □ 跳过备份文件
   □ 详细日志输出
   ```

3. **开始扫描**
   - 点击"开始扫描"按钮
   - 实时查看扫描进度和统计信息
   - 可随时取消正在进行的扫描

#### 扫描结果解读

扫描完成后，您将看到详细的结果报告：

```
扫描统计
├── 文件总数: 156 个
├── 语言文件: 23 个
├── 翻译条目: 1,247 条
├── 已翻译: 892 条 (71.5%)
├── 待翻译: 355 条 (28.5%)
└── 扫描用时: 5.2 秒
```

**文件类型分布**:
- `assets/mod_name/lang/en_us.json`: 英语源文件
- `assets/mod_name/lang/zh_cn.json`: 中文翻译文件
- `META-INF/mods.toml`: MOD 元数据
- `pack.mcmeta`: 资源包元数据

### 3. 翻译管理

#### 翻译条目视图
扫描完成后，可以在翻译管理页面查看所有条目：

| 翻译键 | 源文本 | 目标文本 | 状态 | 操作 |
|--------|--------|----------|------|------|
| `item.example_mod.diamond_sword` | Diamond Sword | 钻石剑 | ✅ 已完成 | 编辑 |
| `block.example_mod.magic_ore` | Magic Ore | _待翻译_ | ⏳ 待翻译 | 翻译 |
| `entity.example_mod.fire_dragon` | Fire Dragon | 火龙 | 🔄 需审查 | 审查 |

#### 翻译状态说明
- **✅ 已完成**: 翻译已完成且通过审查
- **⏳ 待翻译**: 尚未提供翻译文本
- **🔄 需审查**: 翻译已提供，等待质量审查
- **❌ 有问题**: 翻译存在问题，需要修正

#### 批量操作
1. **批量翻译**
   - 选择多个待翻译条目
   - 使用 Trans-Hub 的 AI 翻译建议
   - 一键应用翻译结果

2. **批量审查**
   - 快速审查多个翻译条目
   - 批量接受或拒绝翻译
   - 添加审查意见

3. **批量导出**
   - 选择特定状态的条目
   - 导出为多种格式（JSON、CSV、Excel）
   - 用于外部翻译工具协作

### 4. Trans-Hub 同步

#### 同步配置
1. **连接 Trans-Hub**
   ```
   API 地址: https://api.trans-hub.net
   API 密钥: [您的 API 密钥]
   项目 ID: [关联的 Trans-Hub 项目]
   ```

2. **同步设置**
   ```
   □ 自动同步新条目
   □ 同步未完成的翻译
   □ 包含审查状态
   □ 保留本地更改优先级
   ```

#### 同步操作

**推送到 Trans-Hub**:
1. 选择要推送的内容
   - 新增的翻译条目
   - 更新的翻译内容
   - 状态变更信息

2. 预览推送内容
   ```
   将推送的更改:
   ├── 新增条目: 15 条
   ├── 更新翻译: 8 条
   ├── 状态变更: 23 条
   └── 预计用时: 约 30 秒
   ```

3. 确认并执行推送

**从 Trans-Hub 拉取**:
1. 检查远程更新
   ```
   可用的远程更新:
   ├── 新翻译: 42 条
   ├── 翻译更新: 15 条
   ├── 审查完成: 28 条
   └── 最后同步: 2 小时前
   ```

2. 选择拉取内容
   - 可以选择性拉取特定类型的更新
   - 预览将要应用的更改

3. 处理冲突
   - 当本地和远程都有更改时，选择处理方式
   - 接受远程 / 保留本地 / 手动合并

#### 冲突解决

当同步时发现冲突，工具会提供智能解决方案：

```
发现冲突的条目: item.example_mod.sword

├── 翻译: "钻石剑"
├── 状态: 已完成
└── 修改时间: 2024-01-15 14:30

远程版本:
├── 翻译: "钻石之剑"
├── 状态: 已审查
└── 修改时间: 2024-01-15 16:45

建议操作:
○ 接受远程版本（推荐）
○ 保留本地版本
○ 手动合并
○ 稍后处理
```

## 常见使用场景

### 场景 1: 新 MOD 翻译项目

**目标**: 为一个新下载的英文 MOD 创建中文翻译

**步骤**:
1. 创建新的 MOD 项目，指向 MOD 文件夹
2. 执行完整扫描，提取所有可翻译内容
3. 在 Trans-Hub 上创建对应项目并关联
4. 使用 AI 翻译建议快速生成初版翻译
5. 逐个审查和优化翻译质量
6. 同步到 Trans-Hub 进行协作翻译
7. 构建中文语言包并安装到游戏

### 场景 2: 多人协作翻译

**目标**: 团队协作完成大型 MOD 包的翻译

**步骤**:
1. 项目负责人创建项目并推送到 Trans-Hub
2. 团队成员各自安装 TH-Suite 并连接项目
3. 分配翻译任务（按模组或类别划分）
4. 定期同步获取其他成员的翻译进度
5. 使用审查功能确保翻译质量
6. 处理翻译冲突和协调统一用词
7. 发布最终版本的翻译包

### 场景 3: 翻译更新维护

**目标**: 为已有翻译的 MOD 更新版本维护翻译

**步骤**:
1. 更新 MOD 文件到新版本
2. 执行增量扫描检测新增内容
3. 识别变更的翻译条目
4. 翻译新增内容并更新变更项
5. 验证现有翻译是否仍然适用
6. 同步更新到 Trans-Hub
7. 构建并发布更新的翻译包

### 场景 4: 资源包本地化

**目标**: 为 Minecraft 资源包创建本地化版本

**步骤**:
1. 创建资源包项目类型
2. 扫描资源包中的语言文件
3. 翻译物品、方块、界面文本
4. 适配本地化的纹理和音效命名
5. 验证游戏内显示效果
6. 打包本地化资源包

## 疑难解答

### 常见问题

#### Q: 扫描时提示"无法访问文件"
**A**: 检查以下几项：
- 确认文件路径正确且存在
- 检查文件权限，确保 TH-Suite 有读取权限
- 关闭其他可能占用文件的程序（如游戏客户端）
- 如果是 JAR 文件，确认文件未损坏

#### Q: 同步时连接 Trans-Hub 失败
**A**: 排查步骤：
1. 检查网络连接是否正常
2. 验证 API 密钥是否正确和有效
3. 确认 Trans-Hub 服务状态正常
4. 检查防火墙设置是否阻止连接
5. 尝试重新生成 API 密钥

#### Q: 翻译文件构建后游戏中不显示
**A**: 可能的原因：
- 语言文件放置位置不正确
- 文件编码格式不对（应为 UTF-8）
- JSON 语法错误
- MOD 本身不支持该语言
- 游戏设置中未选择对应语言

#### Q: 程序启动缓慢或卡顿
**A**: 优化建议：
- 增加分配给程序的内存
- 减少并发扫描线程数
- 清理临时文件和缓存
- 关闭不必要的后台程序
- 检查硬盘可用空间

### 错误代码对照

| 错误代码 | 说明 | 解决方案 |
|----------|------|----------|
| E001 | 文件读取权限不足 | 以管理员身份运行或修改文件权限 |
| E002 | 网络连接超时 | 检查网络设置和防火墙配置 |
| E003 | API 密钥无效 | 重新获取和配置 API 密钥 |
| E004 | 磁盘空间不足 | 清理磁盘空间或更改工作目录 |
| E005 | 文件格式不支持 | 检查文件类型和版本兼容性 |

### 性能优化建议

#### 硬件优化
- **CPU**: 多核处理器能显著提高扫描速度
- **内存**: 16GB+ RAM 推荐用于大型项目
- **存储**: SSD 硬盘能大幅提升文件读写速度
- **网络**: 稳定的宽带连接确保同步流畅

#### 软件优化
- 定期清理临时文件和缓存
- 合理设置并发线程数（通常等于 CPU 核心数）
- 使用增量扫描代替完整扫描
- 启用文件监控自动检测变更
