# 先结论

在**不改动 V5 SSOT 核心/运维表结构**的前提下，落地**分层异步增量扫描**，并把“常用包”统一为**近期活跃集 RAS（Recent Active Set）**：

* \*\*快照-Δ（Delta）模型 + 检查点化任务 DAG + 内容寻址缓存（CAS）\*\*三件套；
* **1–2 秒首屏**、**中断可续扫**、**版本更新 O(Δ)**、**键集指纹加速**、**会话级回滚**；
* 仅**新增/细化 cache\_\***（快照与 Δ）与（可选）事件流水表，**core\_\*** 与 **ops\_\*** 不迁移。

# A. 可执行答案（直接落地的完整方案）

## A1. 范围与边界

* **范围**：本地扫描整合包（Modrinth/CurseForge/自定义），抽取**MOD 元信息**与**语言键值**并入库。
* **不做**：JAR/ZIP 二进制长期存储与打包；仅扫描时短读。
* **一致性**：**最终一致**优先体验；写入由**单写入者**批量落库（WAL）。
* **数据库**：SQLite/SQLCipher；保持你 V5 的 `core_* / ops_* / cache_* / cfg_*` 分层。

## A2. 架构与数据流

```mermaid
flowchart LR
  U[点击扫描] --> ORCH[Scan Orchestrator]
  ORCH --> SNAP[Snapshot Builder]
  SNAP --> S_CUR[(cache_scan_snapshots)]
  S_CUR --> DIFF[Diff Engine]
  DIFF --> DELTA[(cache_scan_delta)]
  DELTA --> Q[ops_work_queue (DAG/Checkpoint)]

  subgraph Workers[异步 Workers（仅产事件，不直接写库）]
    ENUM[ENUM: 目录/manifest/中央目录]
    META[META: mods.toml/fabric.mod.json/mcmod.info]
    LANG[LANG: .json/.lang/.properties]
    VERIFY[VERIFY: 去重/冲突/统计/墓碑]
  end

  Q --> ENUM --> EVT[ops_event_log* 或复用 ops_outbox_journal]
  Q --> META --> EVT
  Q --> LANG --> EVT
  Q --> VERIFY --> EVT

  EVT --> APPLIER[Event Applier(单写入者/批量)]
  APPLIER --> DB[(SQLCipher: core_* ops_* cache_* cfg_*)]
  ORCH --> WS[WS/IPC 增量推送]
  APPLIER --> WS
  DB --> UI[渐进式 UI]
```

\* `ops_event_log` 可选；不建也可复用 `ops_outbox_journal` 的幂等机制承载扫描事件。

## A3. 关键体验与 SLA

* **首屏**：点击后 **≤2 秒** 展示 Pack/Version/MOD 列表（Skeleton→实体行）。
* **渐进补全**：10 秒内 ≥30% 行补齐版本/作者/loader/语言数。
* **中断续扫**：异常退出后 **≤1 秒** 恢复进度并优先补齐“上次展开 MOD”。
* **版本增量**：仅 10/300 MOD 变化，总时长 **≤ 首次 20%**。

## A4. 近期活跃集 RAS（替代“长期高命中”）

* **入集条件（任一成立）**：近 **14 天**内打开/扫描 ≥1 次；或存在启用安装；或手动 **pin**。
* **出集**：非 pin 且 14 天无访问自动退出。
* **CAS 配额**：总 3GB，其中 **RAS 专区 1GB**（pin 永不驱逐）；普通区 2GB（LRU）。
* **保留粒度**：对 RAS 的**整合包版本**保留最近 **1 个版本**的解析产物（META/LANG）。

## A5. 指纹与 Δ（Delta）策略

* **轻→重判定**：`size+mtime` → `jar_cd_entries/jar_cd_crc` → **BLAKE3** 全文。
* **Manifest Δ**：Modrinth 比 `files[].hashes.sha512`；CF 比 `(projectID,fileID)`；未变则整包秒过（仅快扫校验）。
* **移动/重命名**：`hash` 不变仅更新路径映射，不重解析。
* **键集指纹（启用）**：

  * `keyset_hash_file = BLAKE3(canonical_json(sorted(keys)))`；
  * `file_hash` 变但 `keyset_hash_file` 不变 → 跳过**键域**重建，仅值域轻 diff。
* **CAS 复用**：`cid = BLAKE3(file_bytes)` 命中即跳过解析，直接产事件。

## A6. 任务 DAG、检查点与事件模型

* **ops\_work\_queue.type** 新增：`scan_enum | scan_meta | scan_lang | scan_verify`（仅加枚举，不改表）。
* **检查点**写 `payload_json`：`{stage, artifact_ref, artifact_hash?, last_step, offset?}`。
* **事件最小集**（UI/落库两用，幂等）：

  * `LIST_UPSERT`（列表行上屏/更新）
  * `FIELD_PATCH`（版本/作者/loader/语言数）
  * `LANG_UPSERT`（language\_file 与 entries 增量）
  * `COUNT_PATCH`（计数/统计）
  * `TOMB_STONE`（删除/移动墓碑）
  * `CONFLICT`（冲突标记）
  * `PROGRESS`（会话/行内进度）
  * `ERROR`（错误徽章与重试）
* **幂等键**：`session_id + event_type + entity_ref + stage + artifact_hash`。
* **优先级矩阵**：可见优先(100) > Δ 变更(70) > RAS 补完(50) > 非 RAS 补完(20)。
* **中断恢复**：恢复后先将“上次展开 MOD”任务 requeue 为最高优先级，再常规调度。

## A7. 数据契约（保持 SSOT 不变，最小增补）

**不改动**：
`core_packs / core_pack_versions / core_pack_items / core_pack_installations / core_mods / core_mod_versions / core_language_files / core_translation_entries / ops_work_queue / ops_outbox_journal / ops_sync_log / ops_cas_objects / cfg_local_settings / cfg_file_watch`

**新增/细化（可再生/可回滚）**：

* `cache_scan_snapshots`：`snapshot_id, session_id, pack_uid, pack_version_uid?, root_path, files_json, created_at`

  * `files_json[i]={path,size,mtime,is_archive,jar_cd_entries?,jar_cd_crc?,hash_short?}`
* `cache_scan_delta`：`snapshot_id, session_id, delta_json{added[],modified[],moved[],removed[],touched_mods[]}, created_at`
* `ops_event_log`（可选）：`event_id, session_id, event_type, entity_ref, stage, artifact_hash?, payload_json, ts`

  * 若不建此表→复用 `ops_outbox_journal` 承载扫描事件。

**索引建议**：`cache_scan_snapshots(created_at)`、`cache_scan_delta(snapshot_id)`；若建 `ops_event_log`，加 `(session_id, ts)` 与 `(event_type, entity_ref)`。

## A8. UI 约定（协议级，不写前端）

* **首屏**：来自 `cache_scan_snapshots` 的列表；Skeleton→实体行。
* **逐列补丁**：通过 `FIELD_PATCH`/`LANG_UPSERT` 上屏；展开某 MOD 即提升优先级。
* **中断提示**：重启 **≤1s** 显示“已恢复至上次进度，优先完成：X”。
* **RAS 与 pin**：列表标识；设置页可 pin/unpin。

# B. 原理与取舍（为什么这样最贴合你的 V5）

* **与 SSOT 对齐**：Pack/Mod/Language/Entry 均为一等实体；扫描仅“补齐事实”，不把 Pack 当 Mod 存。
* **单写入者**：Workers 只产事件；由 Applier 批量写库，避免锁争用与 Busy。
* **最终一致**：先给首屏，后补细节；事件幂等可重放，支持会话级回滚。
* **RAS 简化**：不追求长期命中，“近 14 天 + 安装 + pin”即可；CAS 策略简单可控。
* **键集指纹**：大幅缩短“键不变值变”的解析时间，契合低更新频率的现实。

# C. 落地步骤与清单（实施、配置、验收、回滚）

## C1. 实施 WBS（两周量级，按并行拆分）

1. **契约冻结（0.5 天）**：事件类型/幂等键/队列枚举/检查点字段/快照Δ字段。
2. **阶段1 快扫（2–3 天）**：Snapshot\_curr 生成；首屏 ≤2s；写入 `cache_scan_snapshots`。
3. **Diff & Δ（2 天）**：写入 `cache_scan_delta`；派发 ENUM/META/LANG/VERIFY 子图。
4. **队列与检查点（2 天）**：`ops_work_queue` 新枚举；检查点写 `payload_json`；指数退避重试。
5. **CAS 与键集指纹（2–3 天）**：LANG\_INDEX 产物内带 `keyset_hash_file`；CAS 读写与配额。
6. **Event Applier（2 天）**：单写入者批量落库（`batch_size=200` 或 `flush_interval=500ms`，WAL）。
7. **UI 渐进与可见优先（2–3 天）**：字段补丁、进度、错误徽章、展开→优先。
8. **防护与异常（1 天）**：zipbomb/符号链接循环/大小写编码规范化/黑名单。
9. **压测与验收（1–2 天）**：按 C3 验收矩阵输出报告。

## C2. 配置（写入 `cfg_local_settings`）

```json
{
  "ras_policy": { "recent_days": 14, "min_opens": 1, "respect_active_installations": true, "pin_list": [] },
  "cas": { "quota_gb": 3, "ras_quota_gb": 1, "retention_days": 14 },
  "queue": { "resume_priority": "visible_then_delta", "max_retries": 3, "backoff_seconds": [1,3,7] },
  "delta": {
    "use_manifest_delta": true,
    "file_quick_check": ["size_mtime", "jar_central_crc"],
    "hash_algo": "blake3",
    "use_keyset_hash": true
  }
}
```

## C3. 验收矩阵（必须通过）

* **A-01 首屏**：100–300 MOD，点击后 **≤2s** 出列表。
* **A-02 渐进补全**：10 秒内 ≥30% 行补完关键字段。
* **A-03 中断恢复**：异常退出后 **≤1s** 恢复进度并优先“上次展开 MOD”，无重复解析。
* **A-04 版本增量**：仅 10/300 MOD 变化，总耗时 **≤ 首次 20%**。
* **A-05 移动/重命名**：不触发解析，仅路径更新。
* **A-06 一致性**：事件重放后 DB 与 UI 一致，无孤儿/重复记录。
* **B-01 RAS 命中**：近 14 天访问过的包/版本的二次扫描，平均耗时 **≤ 首次 15%**。
* **B-02 键集指纹收益**：file\_hash 变但 keyset 不变时，解析耗时**下降 ≥40%**。
* **B-03 资源约束**：扫描期 CPU ≤ 60%（4C），峰值内存 ≤ 1.5GB。
* **B-04 失败隔离**：单文件失败不拖累总进度，可单独重试。

## C4. 回滚与降级

* **会话回滚**：按 `session_id` 反向应用 `TOMB_STONE/patch`，回退到 `Snapshot_prev`；
* **降级模式**：CAS/队列异常→切换“阶段1快扫 + 元数据轻扫”，保证最小可用；
* **缓存清理**：删除 `cache_scan_*` 与（可选）`ops_event_log` 可完全回退，不影响 `core_*`。

## C5. 风险与防护

* **mtime 失真** → 回退 `jar_cd_crc` 或全文 BLAKE3；
* **符号链接/循环** → 访问集 + 深度上限；
* **大小写/编码差异** → Windows/macOS/Linux 统一规范化；
* **zipbomb** → `max_entries_per_archive=20000`、`max_uncompressed_ratio=100x`、`max_single_file_uncompressed=256MB`；
* **CAS 膨胀** → RAS 专区 + LRU 驱逐，pin 永不驱逐。
