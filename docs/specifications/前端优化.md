# 先结论（一次定版）

**本地化 TH-Suite（离线/桌面端）**建议采用「**Tauri 2 + React 19（App Router 可选）+ Tailwind Token + shadcn/ui + TanStack Query/Table + React Virtuoso + SQLite/SQLCipher**」的**Rust-first** 技术栈，配合**可插拔的“规则/抽取”插件层**（首选 **Rust 插件**，必要时允许 **Python 子进程插件**）。
这样既能拿到**原生级性能与体积**，又能维持你 Web 端的**一致 UI / 状态范式**，并通过 **SQLCipher + 本地签名清单**保证离线数据安全。

# 可执行答案（选型清单｜可直接落地）

## A. 容器与前端

* **容器**：Tauri **2.x**（Rust 侧 `tauri`、`tauri-build`；启用 `updater`、`shell`、`fs`、`dialog` 等最小权限插件）
* **前端**：React **19** + Vite
* **UI/主题**：Tailwind（**CSS 变量三层 Token：Core/Semantic/Component**）+ **shadcn/ui（Radix）**
* **数据与状态**：**@tanstack/react-query v5**（唯一服务器态）+ URL 同步（在桌面端用于“可分享视图”与深链接）
* **表格/性能**：**@tanstack/react-table v8 + react-virtuoso**（大数据、粘性表头、列固定、拖拽宽度）
* **表单**：react-hook-form + zod（统一校验）
* **命令面板**：`cmdk`（⌘K 快捷操作）
* **图标**：`lucide-react`

## B. 本地存储与加密

* **数据引擎**：**SQLite + SQLCipher**（WAL 模式，`PRAGMA cipher_page_size=4096`，KDF 迭代加固）
* **Tauri 插件**：`tauri-plugin-sql`（或 `tauri-plugin-sqlite`）+ 自定义**加密密钥派生**（密钥不落盘，源于设备指纹 + 用户口令 + 远端盐值）
* **KV/偏好**：`tauri-plugin-store`（非敏感）

## C. 后台任务与原生能力

* **Rust 后台任务**：`tokio` + `anyhow` + `serde` + `rayon`（并行 IO/CPU）
* **解包/扫描/哈希**：Rust 实现（`zip/flate2`、`walkdir`、`xxhash-rust`/`blake3`）
* **网络**：`reqwest`（带重试/断点续传），对象直传按服务端预签名策略
* **自动更新**：Tauri Updater + 你的签名/发布流程

## D. 可插拔“抽取/规则”层（两档备选）

1. **Rust 插件优先**（推荐）

   * 接口：`trait Extractor { fn supports(&self, file: &Path) -> bool; fn extract(&self, src: &Path) -> Result<Vec<Item>>; }`
   * 发布：dlopen 风格或内嵌 feature gate；版本与 UIDA 协议检查
2. **Python 子进程插件（按需）**

   * 启动虚拟环境：随应用携带 **py-embed** 或**打包 venv**（尺寸控制 < 30MB）
   * 通信：**stdin/stdout JSON-RPC**（约定 `extract`, `lint`, `transform` 方法），Rust 侧超时与资源限额
   * 依赖：`pydantic v2`（schema）、`orjson`（序列化）

> 原则：**Rust-first、Python-as-plugin**。避免在 GUI 线程里跑解释器，所有 Python 工作以**子进程**运行，且**离线可替换为纯 Rust**。

## E. 同步与权限

* **鉴权**：JWT + 设备 ID；本地 `tenant_id/user_id` 只作缓存，不做权限判定
* **差量同步**：Manifest（UIDA + 哈希 + 大小 + mtime）→ 计算**分块哈希**支持断点
* **冲突**：三路合并（server/base/local）+ 冲突队列回放
* **安全**：签名清单（服务器侧）+ 本地**只读快照表**，导入/写回全用事务

## F. 测试与质量

* **前端**：ESLint 9 + TS 5 + Vitest + Playwright（关键路径：抽取→浏览→筛选→写回）
* **Rust**：`cargo test` + `cargo nextest`（重度并发）
* **Python 插件（如启用）**：pytest + mypy（限定在 `plugins/python` 子目录）
* **CI**：GitHub Actions（Mac/Win/Linux 三平台构建与签名）

# 原理与取舍（为何这样选）

* **Tauri 2**：原生窗口 + 系统权限 + 体积小（≈5–15MB），更适合你“离线工具 + 大量 FS/CPU”的场景；Electron 体积与内存成本不划算。
* **Rust-first**：IO/CPU 密集、解包/扫描、哈希、分块同步在 Rust 可拿到**数量级性能优势**与更可控的资源占用。
* **SQLCipher**：离线数据库加密 + WAL，兼顾安全与并发；再叠**应用层签名**与**快照表**保证数据完整性与可回滚。
* **前端范式延续 Web 端**：TanStack Query/Table + Virtuoso + RHF/zod，**最小心智切换**，易于共享 UI/逻辑片段。
* **插件层双轨**：Rust 插件是首选（性能/分发），Python 子进程仅在**规则快速迭代或生态复用**时启用。

# 落地步骤与清单（零错误、零失败）

## 1) 仓库结构（示例）

```
th-suite/
├─ apps/desktop/                 # Tauri 2 应用
│  ├─ src/                       # React 19 + Vite
│  ├─ src-tauri/                 # Rust 核心
│  └─ package.json
├─ packages/ui/                  # 共享组件（shadcn 定制 + tokens）
├─ packages/shared/              # 共享模型/UIDA/工具
├─ plugins/
│  ├─ rust/                      # Rust 抽取器（可多crate）
│  └─ python/                    # Python 子进程插件（可选）
└─ docs/                         # SSOT 文档（架构/数据/协议）
```

## 2) 关键基线

* **Token**：拷贝你 Web 的 `tokens.css`，桌面端保持一致品牌/色阶/圆角/阴影
* **表格基座**：复用你已有的 **DataTable（URL 同步 + 视图持久化 + Virtuoso）**
* **数据库**：

  * 启动时 `PRAGMA journal_mode=WAL; synchronous=NORMAL;`
  * 敏感表：行级加密（可选），最少列加密策略
  * 导入/写回：**单事务 + 批量**，失败全回滚
* **签名清单**：

  * 结构：`{ uid: string, path: string, size: int, hash_blake3: string, last_modified: int }[]`
  * 本地/远端清单对齐，按块比对差量
* **Python 插件守护**（若启用）：

  * 启动上限（时长/内存/CPU），异常自动熔断
  * 路径白名单与只读沙箱（避免任意 FS 写入）

## 3) 打包与更新

* Tauri 打包 + 代码签名（Win/ macOS）
* Updater 配置：强校验签名 + 渐进更新通道（stable/beta）

## 4) 自检清单

* [ ] 首次启动 < 1.5s（首屏骨架 200ms 内出现）
* [ ] 1–5 万条表格滚动 **60fps**（固定行高 + 虚拟化）
* [ ] 导入 1GB 资源包：**分块断点**、失败可恢复；导入后快照可回滚
* [ ] SQLCipher：强口令 + KDF > 200k 迭代；密钥不落盘
* [ ] 插件签名与版本检查；规则升级可回退
* [ ] e2e 测试覆盖“抽取→筛选→写回→同步”主干
